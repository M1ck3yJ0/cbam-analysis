# Database Schema — cbam.db

SQLite database generated by `notebooks/08_build_verify_database.ipynb`.
Not committed to the repository — rebuild by running notebook 08 after
completing notebooks 01 through 07.

See schema diagram: `db/schema_diagram.png`

## Tables

### country_crosswalk
**Grain:** one row per country
**Purpose:** single source of truth for all country identifier joins across
the project. Built in `07_clean_transform_data.ipynb` from Ember country
data, extended with pycountry lookups and manual overrides.
**Key columns:** `iso2`, `iso3`, `country` (canonical English name),
`name_cbam_defaults`, `name_ember`
**Primary key:** `country`
**Join key:** `country` for name-based joins, `iso2` for code-based joins
**Rows:** 240

---

### cbam_defaults
**Grain:** one row per (country, cn_code, production_route_code)
**Purpose:** CBAM default emission values published in Commission
Implementing Regulation (EU) 2025/2621. Covers 119 countries and all
CBAM-covered CN codes across six sectors.
**Key columns:** `country`, `cn_code`, `description`, `direct_emissions`,
`indirect_emissions`, `total_emissions`, `default_2026`, `default_2027`,
`default_2028_onwards`, `production_route_code`, `production_route`
**Primary key:** `(country, cn_code, production_route_code)`
**Foreign key:** `country` references `country_crosswalk(country)`
**Join key:** `country` + `cn_code`
**Rows:** 10,671
**Notes:**
- CN codes 25231000 (clinker) and 25239000 have two rows per country,
  grey (A) and white (B) clinker have separate defaults. Handle
  explicitly in any join.
- Non-cement rows have NULL `production_route_code` and are unique on
  `(country, cn_code)`.
- `default_2026` is null for Chile CN 73061100 — confirmed as a dash in
  the legally binding regulation (EUR-Lex page 471/2400).
- Mali CN 28041000 (hydrogen) has all-zero emission values — confirmed
  in source.

### trade_flows
**Grain:** one row per (year, reporter, country, cn_code, indicator)
**Purpose:** EU27 import flows from COMEXT dataset DS-045409, 2020-2024.
Value in EUR and quantity in tonnes stored as separate indicator rows.
**Key columns:** `year`, `reporter`, `freq`, `iso2`, `country`, `flow`,
`cn_code`, `indicator`, `indicator_label`, `value`, `material`
**Primary key:** `(year, reporter, country, cn_code, indicator)`
**Foreign key:** `country` references `country_crosswalk(country)`
**Join key:** `country` + `cn_code`
**Rows:** 154,782
**Notes:**
- EU member state partners are present but not CBAM-relevant — filter
  on `country` via crosswalk to CBAM defaults.
- CN code 761090 removed — confirmed parent of 76109010 and 76109090
  per EU CN nomenclature; retaining all three would double-count.
- 1,747 zero-value rows retained — filter at query time if needed.

---

### grid_co2_intensity
**Grain:** one row per (country, year)
**Purpose:** Grid carbon intensity in gCO2/kWh from Ember yearly
electricity data. Primary input for CBAM indirect emissions calculations.
**Key columns:** `country`, `iso3`, `year`, `co2_intensity_gco2_kwh`,
`continent`, `ember_region`
**Primary key:** `(country, year)`
**Foreign key:** `country` references `country_crosswalk(country)`
**Join key:** `country` + `year`
**Rows:** 5,407
**Notes:**
- Pakistan latest year: 2019. Ukraine latest year: 2022.
- Burundi and Central African Republic have zero intensity values —
  near-zero hydro grids, retained as-is, not treated as null.
- Curacao has no grid data — indirect emissions cannot be calculated.

---

### grid_capacity
**Grain:** one row per (country, year, subcategory, fuel_type, unit)
**Purpose:** Installed electricity generation capacity in GW by fuel type.
**Key columns:** `country`, `iso3`, `year`, `subcategory`, `fuel_type`,
`unit`, `value`
**Primary key:** `(country, year, subcategory, fuel_type, unit)`
**Foreign key:** `country` references `country_crosswalk(country)`
**Rows:** 62,141

---

### grid_generation
**Grain:** one row per (country, year, subcategory, fuel_type, unit)
**Purpose:** Electricity generation by fuel type in TWh and % share.
**Key columns:** `country`, `iso3`, `year`, `subcategory`, `fuel_type`,
`unit`, `value`
**Primary key:** `(country, year, subcategory, fuel_type, unit)`
**Foreign key:** `country` references `country_crosswalk(country)`
**Rows:** 126,388
**Notes:**
- `unit` is required as a key column because Ember reports generation
  in both TWh and % for the same (country, year, subcategory, fuel_type)
  combination.

---

### steel_route_intensities
**Grain:** one row per (production_route, year)
**Purpose:** Global average CO2 and energy intensities by steel production
route. Worldsteel Sustainability Indicators 2025. Benchmark reference only
— not country-specific.
**Key columns:** `production_route`, `year`, `co2_intensity_tco2_per_t`,
`energy_intensity_gj_per_t`
**Primary key:** `(production_route, year)`
**Join key:** `production_route` to `production_route_code` in
`cbam_defaults` via the benchmark annex key
**Rows:** 12
**Notes:**
- Global avg row is a summary reference — exclude from joins.
- DRI-EAF codes (D) and (G) do not appear in cbam_defaults — no country
  was assigned this route by the EU Commission.

---

### hydrogen_intensities
**Grain:** one row per (cn_code, feedstock_type)
**Purpose:** Global average GHG emission intensities per hydrogen
production route. JRC135067. Benchmark reference only.
**Key columns:** `cn_code`, `feedstock_type`,
`total_emissions_tco2_per_th2`, `comments`, `source`
**Primary key:** `(cn_code, feedstock_type)`
**Rows:** 6

## Design Decisions

**Join key:** `country` (canonical English, ASCII only) is the standard
join key across all country-level tables. Built and maintained in
`country_crosswalk.csv`.

**CN codes:** stored as TEXT strings throughout. Mixed lengths (4, 6, 8
digit) are valid and intentional — do not zero-pad.

**Grid data split:** Ember data is split into three tables
(`grid_co2_intensity`, `grid_capacity`, `grid_generation`) rather than
one long-format table, for query performance and analytical clarity.

**Schema-first load pattern:** The database is built using explicit
`CREATE TABLE` statements with full `PRIMARY KEY` and `FOREIGN KEY`
declarations before any data is loaded. Data is inserted via pandas
`to_sql(if_exists='append')` into the pre-declared schema, preserving
all constraints. Foreign keys are declared on all country-level tables
referencing `country_crosswalk(country)`. Enforcement is validated
post-load via `PRAGMA foreign_key_check` in notebook 08, which confirmed
zero violations on the current dataset.

**Pre-schema validation:** All proposed primary keys are verified for
uniqueness against the source DataFrames before the schema is executed.
If any key check fails, notebook execution halts before the database is
written.
